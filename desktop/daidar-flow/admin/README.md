# أداة إدارة التراخيص — Windows فقط

هذه أداة Node منفصلة عن العميل. شغّل البناء أولًا. لا توزع admin-dist أو admin أو vault على العملاء. مجلد العميل التشغيلي هو dist فقط؛ أي مثبت لاحق يجب أن يلتزم بقائمة سماح لهذا المجلد وحده.

المفتاح الخاص يحفظ مشفرًا بـDPAPI تحت حساب Windows الإداري، خارج المستودع. لا يطبع ولا يصدّر بصيغة plaintext. لا تنقل الخزنة إلى جهاز عميل. المصدر يحتوي منطق الأداة فقط وليس المفتاح. احتفظ بنسخة آمنة من حساب/نظام Windows وخزنته؛ نسخ ملف DPAPI وحده لجهاز آخر ليس خطة استعادة. في حال فقدان المفتاح أضف مفتاحًا عامًا جديدًا وأصدر تحديث عميل، ثم أعد الإصدار إداريًا.

تهيئة مرة واحدة (المسار الافتراضي للخزنة `%LOCALAPPDATA%\DaidarFlowAdmin`):

```powershell
node desktop/daidar-flow/admin-dist/license-admin.cjs init --public-out desktop/daidar-flow/src/main/licensing/public-keys.json
```

إذا كان ملف المفاتيح العامة موجودًا فالمشروع مهيأ: لا تعِد التهيئة فوقه. أداة الإدارة الحالية تحتاج الخزنة الأصلية. لتدوير المفتاح، استخدم خزنة خارجية جديدة و`--public-out` جديدًا، ثم ادمج المفاتيح العامة فقط داخل public-keys.json ووزّع إصدار العميل المحدث. لا تستبدل الجذر سرًا. `--vault` يسمح باختيار خزنة خارجية.

إصدار شهر/3/6/12 (المدة بالشهور الميلادية مع ضبط نهاية الشهر، تبدأ الآن أو `--start` بصيغة UTC ISO):

```powershell
node desktop/daidar-flow/admin-dist/license-admin.cjs issue --device "DFD1-..." --customer "اسم العميل" --months 3 --out "$env:USERPROFILE\Documents\customer-license.dfl"
```

لا يقبل DFD1-... المختصر؛ انسخ المعرف كاملًا من صفحة التفعيل. كل الميزات المدفوعة افتراضيًا؛ للتخصيص استعمل `--features analytics,employees`. حرية الميزات المجانية لا تتأثر. سلّم ملف .dfl أو محتواه ككود، واحتفظ بسجل ledger.json داخل الخزنة. `inspect --previous <file>` يفحص التوقيع ويعرض تفاصيل الملف.

تغيير الجهاز: تحقق إداريًا من هوية العميل، استلم Device ID الجديد، واطلب إزالة التفعيل/إيقاف استخدام الجهاز القديم. ثم:

```powershell
node desktop/daidar-flow/admin-dist/license-admin.cjs reissue --previous "$env:USERPROFILE\Documents\customer-license.dfl" --device "DFD1-..." --reason "تغيير اللوحة الأم بعد التحقق من العميل" --confirm-transfer --out "$env:USERPROFILE\Documents\customer-reissued.dfl"
```

تحفظ نفس بداية ونهاية وميزات الاشتراك ولا تمده؛ يسجل مرجع الترخيص السابق والسبب، ويمنع إعادة نقل السجل القديم مرة ثانية. يظل الكود القديم صالحًا على الجهاز القديم حتى نهايته إن كان Offline: السجل الإداري لا يرسل إلغاءً عن بُعد. الإلغاء الفوري المضمون يحتاج خادم إلغاء مستقبليًا.

لا تحذف admin.lock تلقائيًا إن تعطلت الأداة؛ تأكد أولًا من عدم وجود عملية إدارة تعمل، ثم أزل ملف القفل فقط بعد المراجعة. ملفات تراخيص العملاء وسجلهم خارج Git. الأداة ترفض حفظ الخزنة أو ملفات العملاء داخل المستودع.

يُحفظ الكود الموقّع في السجل قبل كتابة ملف التسليم. إذا فشلت كتابة الملف أو انقطعت العملية بعدها، استعد الكود نفسه بدون إصدار أو تمديد جديد: `export --license <license-id> --out <external-file.dfl>` مع نفس `--vault`. يمكن معرفة المعرف من ledger.json؛ يرفض تصدير سجل جرى استبداله. احمِ السجل لاحتوائه أسماء العملاء وتراخيصهم.
