# نتائج المرحلة الثانية — نظام التراخيص

## النتيجة والنطاق
اكتملت المهام11–16 بالتتابع، مع فحص كل مهمة قبل التالية. بقيت01–10 مكتملة، و17–18 Pending. المهمة16 هنا خاصة بحماية التراخيص؛ Code Signing وfuses وتقوية حزمة التوزيع والتحديثات ضمن17. لا وظائف مخزون أو بيع أو كاشير أو قاعدة بيانات أعمال أو Installer في هذا التغيير. واجهة الكروت والناف بار المختصر محفوظة؛ أضيف التفعيل والتنبيه فقط.

## المنفذ
- Device Fingerprint من مصدرين صالحين على الأقل من MachineGuid وSMBIOS UUID وBIOS، بدون MAC. تطبيع ورفض placeholders؛ DFD1 قابل للنسخ؛ لا حفظ/إرسال لمعرفات خام. ذاكرة محمية للمدخلات المختارة عند تعطل المزود مؤقتًا. تغيير Windows/اللوحة الأم قد يحتاج إعادة إصدار.
- صيغة DFL1 مستقلة عن Hub، Ed25519، توقيع canonical UTF-8، مخطط صارم، استيراد كود أو ملف محدود16KiB. تحقق من الجهاز والميزات والتواريخ في Main لكل طلب مدفوع.
- أداة admin مستقلة بمدد1/3/6/12 شهرًا ميلاديًا وضبط نهاية الشهر، ميزات صريحة، سجل خارجي، وفحص/تصدير لاستعادة ملف تسليم. إعادة الإصدار تتطلب ملفًا سابقًا معروفًا ومعرفًا مختلفًا وسببًا وتأكيدًا، وتحافظ على تاريخ البداية والنهاية والميزات.
- مفتاح حقيقي أُنشئ داخل خزنة DPAPI CurrentUser خارج Git تحت `%LOCALAPPDATA%\DaidarFlowAdmin`. العميل والمصدر يحملان المفتاح العام فقط. الاختبارات تستخدم مفاتيح مؤقتة تمحى؛ لا تصدر اشتراكات اختبار بالمفتاح الإداري الحقيقي.
- صفحة «التفعيل والاشتراك» تعرض الحالة والعميل والبداية والنهاية والعدّاد والمعرف. تنبيه120 ساعة قبل الانتهاء، تحديث كل ثانية/عند focus، قفل المدفوع في Main عند النهاية الدقيقة وبقاء المجاني. الكروت المفعّلة ما زالت تعرض «قريبًا» لأن وظائفها خارج النطاق.
- DPAPI async بدون plaintext fallback، حفظ ذري، single-instance، طابور معاملات. high-water وmonotonic، سماح5 دقائق لتراجع الساعة دون تمديد صلاحية، sticky review عند التراجع الأكبر، ورفض تجاوزه باستيراد كود. حفظ كل30 ثانية وعند العمليات الحساسة؛ لا حذف بيانات عند الانتهاء.

## الملفات
`src/main/licensing/`: protocol, device, service, storage, bounded file reader, public roots.
`admin/`: الأداة ودليل الإصدار/نقل الجهاز/استعادة الملف.
`src/shared/licensing.ts` وعقود preload/IPC، `ActivationPanel.tsx` وApp/CSS، build/test scripts.
`tests/`: protocol, device, administrator, service/time, distribution separation، native activation/integration.
تحديث tasks11–17 وREADME وARCHITECTURE وLICENSING وWORK_NOTES و.gitignore. لا تغييرات على منطق الموقع أو تراخيص Hub.

## التحقق
- البناء وTypeScript للحزمة نجحا.
-16 اختبار Node في المجموعة الكاملة: سياسة الميزات وروابط الشركة، البصمة، توقيع وتعديل الترخيص، schema/encoding/مدد، أداة Windows DPAPI الفعلية والنقل والاستعادة، عزل dist عن signer والأسرار، الجهاز والحفظ والانتهاء والبداية المستقبلية والساعة.
- Electron حقيقي: Splash وسياق معزول، واجهة بدون إنترنت وروابط آمنة، المقاسات1280/768/360، فشل التهيئة وإعادة المحاولة.
- اختبار تفعيل native يبني نسخة مؤقتة من Main الإنتاجي بجذر اختبار مؤقت، بدون override إنتاجي للمفتاح: تفعيل كود وملف، نسخ المعرف، حجم الملف، رفض mismatch، استعادة DPAPI بعد restart، رفض مفتاح الاختبار بالعميل الإنتاجي، عدّاد/تنبيه خمس أيام، انتهاء فعلي عند guard، المجاني مستمر، rollback وrestart، تخزين تالف يفشل آمنًا ولا يحذف ملف بيانات موجودًا.
- لم تغير الاختبارات ساعة Windows الحقيقية أو حالة تفعيل المستخدم؛ استخدمت profiles مؤقتة ومحاكاة الوقت داخل Main الخاص بالاختبار. لم تُفتح روابط فعلية أو ترسل رسائل.
- الفحص على Windows الحالي؛ مصفوفة أجهزة/OEM/VM وحسابات Windows مختلفة واختبار المثبت الفعلي مؤجلة قبل التسليم التجاري.

## التشغيل والإدارة
من جذر المشروع: `npm --prefix desktop/daidar-flow start`، ثم زر «التفعيل والاشتراك».
الإدارة: `npm --prefix desktop/daidar-flow run build` ثم أوامر [admin/README.md](admin/README.md). الخزنة مهيأة على هذا الحساب: لا تعِد init أو تستبدل المفتاح. لا توزع admin-dist أو الخزنة مع العميل؛ مستقبلًا dist فقط بقائمة سماح. احتفظ بنسخة احتياطية محمية لحساب/نظام Windows والخزنة وسجلها.

## الحدود المتبقية
Offline لا يضمن الإلغاء الفوري على جهاز قديم، أو مقاومة snapshot كامل/حذف كل الحالة/استنساخ VM/تزوير العتاد/تعديل binary. DPAPI لا يمنع كودًا خبيثًا يعمل بنفس حساب Windows. عند نقل الجهاز يلزم إجراء إداري لإيقاف القديم؛ منع الاستخدام المتزامن المضمون يحتاج خادمًا. ملف DPAPI لا يستعاد على أي حساب عشوائي بمجرد نسخه. لا أسرار أو مدفوعات في العميل، ولا ادعاء DRM كامل. راجع [العقد والتهديدات](LICENSING.md).
