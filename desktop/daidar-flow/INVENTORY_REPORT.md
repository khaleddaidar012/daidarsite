## قاعدة البيانات
`app.getPath('userData')/inventory.sqlite`، افتراضيًا `%APPDATA%\daidar-flow-desktop\inventory.sqlite` على Windows. الجداول: products وschema_migrations. Migration1 داخل transaction؛ يرفض مخططًا أحدث ولا يحذف أو يعيد إنشاء قاعدة تالفة. WAL، synchronous FULL، foreign_keys ON وbusy_timeout3000ms.

products: UUID، name، search_name، selling_price INTEGER بالقروش، barcode TEXT nullable، quantity INTEGER بأجزاء الألف، unit، created_at/updated_at UTC، is_active وrevision. Unique index للباركود غير الفارغ، وفهرس active/created/id. الباركود المحذوف منطقيًا يبقى محجوزًا حمايةً للربط المستقبلي. revision يمنع تحديثًا قديمًا من الكتابة فوق تعديل أحدث.

السعر صفر مسموح، دقة2 للعملة و3 للوزن/الحجم، والكميات الصحيحة فقط للقطعة/العلبة/الكرتونة. يقبل الإدخال العربي واللاتيني للأرقام ويحوّل من النص إلى integer دون حساب float. حد المخزون المنخفض5 وحدات، والثلاث حالات لا تعتمد على اللون وحده.

## تجربة الاستخدام
كارت المخزون يفتح الشاشة داخل التطبيق. بحث بالاسم/الباركود وإجمالي حقيقي؛30 منتجًا لكل صفحة وdebounce200ms وتجاهل الردود القديمة. كروت3/2/1 متساوية الارتفاع، وأسماء/باركود قابلة للالتفاف دون قص. نموذج قابل للفتح والإغلاق داخل الصفحة بحركة200ms وreduced-motion، نفس النموذج للتعديل، نجاح مؤقت بعد الحفظ، ومدخلات محفوظة عند الفشل. حذف بعد تأكيد ويعطّل فقط. لا بيانات تجريبية في التطبيق الفعلي.

## الاختبارات
-3 اختبارات Node/SQLite: قيود وترحيل وحفظ بملف وإعادة فتحه، كل حالات التحقق/الوحدات والصفر والكسور والتعارض والحذف المنطقي، و10 آلاف منتج للبحث/التصفح/SQL injection وescaping.
- Electron حقيقي: الشاشة الفارغة والتنقل، الكروت والأسماء الطويلة وحالات المخزون، النموذج والتركيز والإلغاء بدونModal، إضافة/تعديل وتحديث كروت وإجمالي، تأكيد/إلغاء حذف، barcode HID-style وEnter مزدوج، تكرار الباركود والأصفار والقيم nullable، بحث وتصفح، أخطاء بيانات/IPC مع الاحتفاظ بالمسودة.
- تكامل: استمرار البيانات بعد إغلاق التطبيق وإعادة تشغيله، Offline بدون طلباتHTTP أو pageerrors، رفض IPC من نافذة ثانية رغم نفس origin/preload، حفظ المنتج المعطل فيSQLite، وعدم حذف/استبدال قاعدة تالفة أو ادعاء أنها فارغة. تحقق1280/768/360 من grid والارتفاعات وعدمoverflow وصور محلية فيartifacts/ المستثنى من Git.
- بحث جزئي نموذجي على10 آلاف منتج استغرق نحو8–17ms على الجهاز الحالي؛ هذا قياس محلي وليس ضمانًا لكل الأجهزة. البحث contains يفحص النصوص خطيًا، والواجهة تظل محدودة30 صفًا. FTS/worker مستقبلًا إذا تضخم الكتالوج.
- مجموعة التراخيص/الأمان السابقة16 فحصNode واختبارات Electron أُعيد تشغيلها مع المخزون؛ لم تُغير أي قواعد تفعيل أو مفاتيح.

الأوامر: `npm --prefix desktop/daidar-flow run test:inventory`، والمجموعة الشاملة `npm --prefix desktop/daidar-flow test`. كل قواعد وبيانات الأمثلة فيprofiles مؤقتة تُحذف بعد الاختبارات. صور المعاينة فقط تحتوي أمثلة اختبار، ولا تضاف عند تشغيل التطبيق.

## القيود المتبقية ونقطة التوقف
- لم يتوفر ماسحUSB مادي؛ اختُبر مسار Keyboard HID بمحاكاة ضغطات مفاتيح وEnter داخل Electron. الأجهزة التي تتطلبSDK خاصًا خارج النطاق.
- وحدة مخزنية واحدة لكل منتج؛ الكسور حتى3 أرقام، والأسعار حتى رقمين بعد الفاصل. حد منخفض5، ولا واجهة إعداد عتبة أو استعادة منتجات معطلة الآن. barcode المنتج المعطل لا يعاد استخدامه.
- SQLite غير مشفرة في هذه المرحلة، وتحميها صلاحياتWindows؛ لا نسخة احتياطية تلقائية أو تصدير/استيراد أو Installer جديد. لا تعالج أخطاء قاعدة البيانات بحذفها؛ احتفظ بالملف وأغلق البرنامج وراجع الإدارة لاستعادة نسخة سليمة. سلامة الملفات عند انقطاع طاقة مفاجئ تعتمد أيضًا على القرص/النظام؛ اختُبرت إعادة تشغيل التطبيق العادية، ولم يُختبر فصل طاقة فعلي.
- اختبار على Windows الحالي؛ قبل التوزيع التجاري يلزم فحص أجهزة أخرى والمثبت. لا نشرCloudflare من نجاح push؛ التطبيق مستقل.
