## ما اكتمل بالكود والتحقق المحلي
- فحص وإعادة استخدام المشروع الحالي دون مشروع بديل: Next/Pages Hub، Vite/Pages Store، مصدران D1 وطبقة هوية مركزية.
- هب: رئيسية بسيطة بأربع خدمات، سلايدر خمس خدمات كل أربع ثوان، إيقاف يدوي/تركيز/تحويم/إخفاء الصفحة واحترام reduced motion. خدماتي والاشتراكات والحساب وتفاصيل الخدمات، RTL/LTR وروابط عودة مقيدة.
- لوحة العميل تقرأ متجره واشتراكاته وطلباته من المصادر الحقيقية حسب روابط ملكية الهوية. لا بيانات عملاء آخرين أو حسابات مالية خاصة. Flow يظل برنامجًا مثبتًا، دون رابط تشغيل ويب أو إصدار ترخيص من SSO.
- لوحة إدارة واحدة بأقسام العملاء والمتاجر والأنظمة والخدمات والاشتراكات والطلبات والأسعار والإعدادات والتدقيق. تعيد استخدام منطق الإدارة الحالي عبر API محمي server-side، بلا iframe. /admin ووظائف الموظفين والمشروعات القديمة محفوظة.
- طلبات الاستشارة وإدارة السيستم تحفظ داخل hub_orders بقيمة محسوبة على الخادم ومعرف عملية يمنع إعادة الطلب عند تكرار الإرسال. الموافقة على متابعة الطلب لا تؤكد الدفع ولا تنشئ اشتراكًا مدفوعًا.
- ربط الخدمة اليدوية بالهوية يحتاج اختيارًا إداريًا وتأكيد ملكية؛ لا ربط بالاسم أو الهاتف أو تشابه البريد.
- الدخول الموحد: جلسات host-only HttpOnly Secure، PKCE وأكواد استخدام واحد، ربط الحساب القديم بكلمة المرور، خروج عائلة الجلسات، تحقق توقيع/nonce Google. استخدام callback الإنتاج المسجل /api/hub/google/callback دون تغيير Google Cloud أو المفاتيح.
- منع عمليات المتجر والطلبات الجديدة عند اشتراك مستقبلي أو منتهٍ أو تواريخ غير صالحة.

- بعض وحدات إدارة Hub الموروثة عربية داخل shell إنجليزية؛ ترجمتها الكاملة ليست مكتملة.
- MFA تطبيقية غير مطبقة. لا تغيير لمثبت Flow أو مخطط تراخيصه أو مفاتيحه أو وظائف البيع/المخزون في هذه الدفعة.
